# Dead-code check — 2026-11-04

Scope: `apps/api/src`, `apps/api/prisma`, `apps/api/scripts`, `apps/api/serverless`,
`packages/shared-types`, and `apps/web/next-monorepo/apps/web`, excluding
`node_modules`, `.next`, `src/generated/prisma` and build output. The import graph
covers 207 modules; the symbol scan covers 200 modules and 625 exported symbols. The
audit itself was read-only; the cleanup was applied afterwards and is recorded in
`CLEANUP-2026-11-04.md`.

This report supersedes the 2026-10-06 dead-code audit in this folder. That audit's
headline ("0 source files with no application entry path") is no longer accurate:
the tree has changed since, and several features were removed from the backend while
their callers stayed behind.

## Headline

About **600 lines** of application code have no reachable caller. They fall into six
clusters; two of them are not just dead weight but broken wiring that a user can hit.

| # | Cluster | Reachability | Approx. size |
| --- | --- | --- | ---: |
| 1 | Kiosk return-request feature (controller + client + model) | no route, no UI | 105 lines API + ~32 lines web |
| 2 | EOD run-time endpoint (`/api/devices/eod-time`) | no route, but the UI calls it | 7 lines API + 54-line scheduler + client call |
| 3 | `MothershipPairingPanel` component | no importer | 65 lines |
| 4 | Dead `backend-api.ts` client functions | no caller | 24 functions, ~225 lines, ~114 lines of types |

## 1. Kiosk return-request feature is never mounted

`apps/api/src/controllers/Kiosk/kiosk.controller.ts` defines three handlers —
`requestKioskReturn` (line 346), `getKioskReturnRequests` (line 380) and
`approveKioskReturn` (line 407), plus `returnableKioskStatuses` (line 343). The block
is lines 343–447, about 105 lines.

`apps/api/src/routes/Kiosk/kiosk.routes.ts` imports only `batchCreateKiosks`,
`getKiosks`, `getKioskById`, `assignKiosks`, `deactivateKiosks`, `removeKiosk`,
`updateKioskStatus` and `getInventorySummary`. No route registers the three return
handlers, and no other router does either. Repository-wide search finds only the
definitions, one self-referential comment at `kiosk.controller.ts:316`, and the
matching client wrappers.

The client half is dead too: `apps/web/.../lib/backend-api.ts:736,743,748`
(`requestKioskReturn`, `fetchKioskReturnRequests`, `approveKioskReturn`) have zero
callers, and no component imports them. The Prisma model `KioskReturnRequest` and
migration `20261012120000_add_kiosk_return_requests` are used by application code
only through these handlers.

Consequence beyond dead code: the comment in `removeKiosk` says Partners "return it
through requestKioskReturn instead" (`kiosk.controller.ts:315-316`), but that endpoint
does not exist; the actual response is 403 "Only Distributors can deactivate kiosks"
(`kiosk.controller.ts:317-319`). A Partner therefore has no API path to return a
kiosk. Git history shows the handlers were added in `5262896` but a `return-requests`
route has never existed under `apps/api/src`.

Decision needed: either mount the three routes and build the UI, or retire the
handlers, the client wrappers, `KioskReturnRequest` and its migration (with a new
migration, not by editing history).

## 2. EOD run-time endpoint is missing, and the UI still calls it

`apps/api/src/controllers/Admin/device.controller.ts:73` exports
`setEodPricingRunTime`, which validates `{ time }` and calls
`setRunningEodPricingTime`. `apps/api/src/routes/Admin/device.routes.ts` does not
register `/eod-time`; no other router does. A `eod-time` route has never existed in
git history.

The frontend still uses it: `apps/web/.../lib/devices-api.ts:175` posts to
`/api/devices/eod-time`, and `components/devices/DevicesScreen.tsx:799` calls it as
the **first step of scheduling a device price**. Because the route is absent, that
request fails before `setDeviceGamePrice` runs, so the "scheduled" price flow cannot
complete. This is the most user-visible item in this report.

The helper behind it is also dead: `apps/api/src/services/Mothership/eod-pricing.scheduler.ts`
(54 lines) is never started. `startEodPricingTimer` (line 15) has no caller, and
`setRunningEodPricingTime` (line 6) is called only by the unmounted controller.
The durable path is the BullMQ worker (`workers/devicePricing.worker.ts`), which
uses `upsertJobScheduler('eod-midnight', ...)`; the in-process timer is an unused
fallback.

Decision needed: mount `POST /api/devices/eod-time` (and keep the timer only if it
is meant to run without Redis), or remove the handler, the scheduler module and the
frontend call. Do not leave the current state: the UI offers an action that cannot
succeed.

## 3. `MothershipPairingPanel` is orphaned

## Method and verification

Read-only static analysis, no runtime, browser or database mutation:

```powershell
# Baseline: both pass with exit code 0
npx.cmd tsc --noEmit -p apps/api/tsconfig.json
cd apps/web/next-monorepo/apps/web; npx.cmd tsc --noEmit

# Dead locals/imports: 16 API diagnostics, 4 web diagnostics
npx.cmd tsc --noEmit -p apps/api/tsconfig.json --noUnusedLocals --noUnusedParameters
npx.cmd tsc --noEmit --noUnusedLocals --noUnusedParameters

# Unreachable-code check: 0 diagnostics in both projects
npx.cmd tsc --noEmit -p apps/api/tsconfig.json --allowUnreachableCode false
npx.cmd tsc --noEmit --allowUnreachableCode false
```

The import graph was built with the TypeScript AST over 207 modules (relative
imports, `.js`→`.ts`, `@/`, `@shared-types/`, `@workspace/ui/`, literal dynamic
`import()`), then every candidate was re-checked with a repository-wide word-boundary
search that included `audits/` and the web check scripts. Route wiring was checked by
comparing each controller export against the names actually registered in
`apps/api/src/routes`; every mounted router is imported by `app.ts`.

Limitations: computed import specifiers, external consumers of the API, CSS class
usage and string-built URLs are out of scope. Line counts are static and include
blank lines inside dead blocks. The cleanup applied after this audit is recorded in
`CLEANUP-2026-11-04.md`.

## Suggested cleanup order

1. Decide product intent for kiosk returns and EOD run-time. Mount or retire; do not
   leave the UI calling a missing route.
2. Delete `MothershipPairingPanel.tsx` (zero importers).
3. Delete the 24 dead `backend-api.ts` functions and their types; keep
   `fetchOrderRequestSuppliers`.
4. Delete dead exports (`emailStrong`, `emailDivider`, `emailPanel`,
   `emailDisclaimer`, `assetDir`, the five shared-types symbols) and the unused
   imports/locals listed in section 6.
5. Remove unused dependencies; keep `@radix-ui/react-dialog`.
6. Update the four stale AGENTS.md claims.

Re-run both typechecks after each step. Removal is behaviour-neutral only for symbols
with zero references; the two wiring gaps must be decided, not silently deleted.
